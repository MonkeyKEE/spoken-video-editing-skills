# 口播视觉包装（多风格）

## 适用与边界
这是核心工作流中的包装步骤，通过加载风格包完成视觉和声音包装，不是把某一种样式写死在技能里。输入应包含已对齐的底视频、终速干声、逐句字幕、segments/frame_map、内容剪辑计划，以及当次项目配置。先执行配套技能 [spoken-video-editing-qc](../spoken-video-editing-qc/SKILL.md)；若时间轴尚未对齐，或还没有内容剪辑计划，停止包装。

安装本技能时，必须同时提供整个 `styles/`、`contracts/`、`config/`、`examples/` 和 `docs/operations.md`。风格从 [catalog.yaml](../../styles/catalog.yaml) 注册表读取，新增方法见 [styles/README.md](../../styles/README.md)。只拿到本 `SKILL.md` 时，先索取完整仓库或让用户贴上所选 `style.yaml`，不要凭记忆补造颜色、坐标或字体。

若还看到同级的 [black-neon-talking-head](../black-neon-talking-head/SKILL.md)，那只是旧路径兼容引导，不是第二套包装流程，也不含风格配置；风格定义在 `styles/black-neon-talking-head/style.yaml`。当前仓库里唯一 `verified-sample` 风格是 `black-neon-talking-head`。它可以作为样片风格被项目选用，但不是所有品牌的默认风格。`_blank-template` 只能复制，不能直接出片。其他新风格在被验证前应为 `draft`，交付时如实标明；不得把它们宣传为仓库已验证样片。

区分已确认品牌规范、单次作品参数和建议。一品牌确认过风格，不等于另一品牌也永久确认。不把一次实施坐标、字体替代方案、音乐电平当全局规定。原片、工程路径和人物身份属于项目资料，不写进通用模板或风格包。

## 加载、合并与报错
1. 读取项目中的 `style.id`（及可选的版本钉扎），在 `styles/catalog.yaml` 查找登记项并打开对应 `style.yaml`。
2. 按 [config-contract.yaml](../../contracts/config-contract.yaml) 合并：可选起始预设 < 风格包 < 项目 `overrides`。然后检查安全底线。
3. 出现未知风格、选中模板风格、配置模式不兼容、缺少必填项、共享文件含绝对路径或字体文件路径、风格规定固定弹卡频率、或试图关闭直接视听验收/不自动发布/单一语速/禁止 padding 掩盖错位等锁定规则时，按契约报错并停止出片，不要用默认值悄悄继续。
4. 合并结果写成当次 `resolved_config_snapshot`，供渲染和验收使用。

风格包应自包含：颜色、字体族与 fallback、相对坐标布局、安全区、字幕、人物窗、卡片类型、动效、音效、BGM、结尾和资产版权来源都写在风格目录内。不要依赖宿主特定路径。字体只写族名，由当次环境解析；解析规则见风格中的 fallback 与 [operations.md](../../docs/operations.md)。

## 内容计划优先于包装
先根据内容剪辑计划产出场景表：最终时间窗、布局、关键词、动画、引用事实与素材。卡片出现与否、出现时机和文案都由内容决定，风格只提供可用的卡片类型和运动词汇。不得按「每隔几秒弹一张卡」或「每张卡都出音效」自动铺满。

源时间必须通过剪辑表转换到最终帧号；不能另写一套近似时间或再次变速底视频。长文缩短，不遮字幕不压脸。无真实现场素材时使用抽象图形、列表、示意动画，并保持其示意性质；不能杜撰活动记录。活动时间地点价格报名入口无依据时留空或标待公布。

## 视觉与安全区
按风格包实施颜色、点阵或背景、人物窗、字幕和标题。布局使用相对画幅的坐标，并按每条原片显示方向重新标定发顶、脸框、下巴与视线。默认完整保留头顶，卡片名牌不得压脸。车内近景或头顶紧的镜头优先关闭放大，使用缩小人物窗与发顶锚定。微推近仅在风格与项目都允许、且确有余量时使用，检查全过程而非单帧。

标题位置必须低于旧版贴顶做法，并经过目标手机安全区校验：先渲染标题、名牌、各人物布局、最大卡片、字幕和结尾的关键帧；测量文字实际墨水包围盒；按目标平台当时 UI 做留边与铺满两种预览。具体状态栏高度不能当永久常数。旧版贴顶标题属于待修问题，不是可复用目标；新片调整安全区不能顺手改用户未要求重做的旧片。

若选用 `black-neon-talking-head`，其近黑点阵、荧光绿描边多布局人物窗、句级白字幕和稀疏音效是该风格的样片语言，仍须按当次人脸和安全区重测，不得把文件中的起始比例当成不可改的硬坐标。

## 音效、配乐与结尾
人声主导。音效是否出现、出现在哪些节点，要同时满足风格策略和内容计划，不强制每卡出声，不照抄其他时长作品的音效条数。音乐用合法可说明来源的无歌词垫乐或按项目要求选择；不盖口播是听验目标，不能把所谓音量百分比机械等同某分贝差。先测说话时段电平，再试听与duck。只改音乐时从独立干声、音效、新音乐重混，复制视频流并校验画面保持不变，详见剪辑质检技能。

结尾保留自然余韵，最后一帧静帧配品牌淡出。按语义与尾音定时长，不把某一秒数写成硬规则；不得倒放或循环人物伪装新动作。

## 渲染与验收
Python逐帧构图与 FFmpeg 分块渲染是一种已验证的实现路径，但本仓库不附带可直接执行的渲染脚本，需按本流程自行准备或复用项目已有脚本。采用现有脚本前核对配置，勿将脚本硬编码当规范。读帧索引与最终时间轴一致，分块可断点恢复，块接缝PTS连续；尾部静帧只延长图形时间，不重复人声。

导出规格以项目配置为准。仓库中的画幅、帧率、码率、响度和语速数值都是可选起始预设，不是所有平台的硬规范。

验收必须含：关键帧、每种实际用到的布局、手机留边/铺满安全区、脸框碰撞、实际读帧索引、字幕难点、人声与音效、尾巴，以及卡片是否都能回溯到内容计划。将最终视频或同时间轴代理交给可直接播放的审片环节，视听片头、片中、片尾及风险时间段，并配合音画质检。videoReview 是部分宿主环境提供的审片能力，不是公开命令行工具；若宿主提供该能力，可以使用。宿主没有该能力时，必须做等价的人工视听审片，不得跳过，也不得在未看未听时声称已经审过，也不得用联系表替代。无直接审片时只交待审预览，明确未完成项；不宣称逐帧完美，也不把某个风格写成全品牌已确认。完整清单见 [operations.md](../../docs/operations.md)。
