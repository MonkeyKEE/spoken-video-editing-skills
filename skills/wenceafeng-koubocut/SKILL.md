# 文策阿峰IP · 竖屏口播剪辑

本技能根据用户指定的 GitHub 仓库完整规范部署，是文策阿峰的独立入口。2026-11-17用户已明确区分品牌：**文策阿峰竖屏、不带青年磁场MC Logo；青年磁场横屏、带MC Logo。** 原来误放在本名称下的MC流程已迁移到 `qingnian-cichang-koubocut`，不要沿用历史会话里旧版本的MC默认值。

## 先确定品牌，再调用插件

- 用户明确说“做文策阿峰”“剪阿峰口播”时直接选择本技能，不再重复询问已确认的品牌。
- 用户说“做青年磁场”“青年磁场MC”“MC口播”时，不执行本技能；加载 `qingnian-cichang-koubocut`。
- 人物相同、原片横竖方向、上一条工程品牌，都不能覆盖本次用户明确指定的品牌。否定或比较中的MC名称不是制作目标。
- 两个品牌都要时分别创建版本；确有歧义时再问。用户明确单次覆盖时只作用于本次，不修改另一个品牌的默认规则。
- 先读[品牌配置](references/brand-profile.json)和[ChatCut插件执行桥接](references/chatcut-plugin-bridge.md)。本技能须实际使用已有ChatCut插件/原生工具编辑与导出；不是只产出文字计划，也不提供虚构的一键渲染器。

## 文策阿峰专属规则

1. **竖屏**，常规以9:16排版；分辨率和fps按当次要求及素材能力选择。不能静默沿用MC横版画布；不能把前一次MC的1080p60变成本品牌永久默认。
2. **不带青年磁场MC Logo**：片头、常驻水印、人物窗、MG、B-roll覆盖层和片尾都不得残留MC标识。用户未提供其他标识时，不擅自添加品牌水印或伪造Logo。
3. 使用本地配套的 `black-neon-talking-head` 已验证样片语言：近黑点阵底、荧光绿人物窗、白色句级粗字幕、稀疏且人声主导的声音设计。其当前数值、字体族、布局、安全区以[上游风格文件](references/upstream/styles/black-neon-talking-head/style.yaml)为准。
4. 字幕按句呈现，不默认逐字高亮。标题按风格使用绿色/白色分层并避开平台顶部栏；人物完整保留头顶，默认不微推近。
5. 按内容选择大窗、圆形、左右或其他已定义布局，不能把MC“B-roll期间左下圆形人物”套成此品牌的必选动作。不能把MC海军蓝、暖白、署名、固定版式复制过来。
6. 上游片尾的品牌淡出不等于授权添加MC Logo；无阿峰标识时保留自然收尾/静帧，按本次明确要求处理署名。
7. 用户给了参考片或明确字体时优先匹配；缺字体须记录替代并说明，不能声称已经使用完全相同的原字体。

## 已验证版式：上方演示、中间字幕、下方真人圆窗

- **适用**：参考片或当次要求为竖屏上下结构、原素材为真人口播、上方需要轮流展示标题、案例或流程时，优先用这套已验收版式。其他叙事可沿用品牌已有布局，不把上下结构强制用于所有阿峰片。
- **先锁口播、再分区**：先从原声剪出短句和完整语义，用前三秒抛观点或具体场景，不用硬加速塞进时长。上方为花字、Remotion MG 与 B-roll 的共用展示区；在不同段落切换，不把同一说明塞满三层。B-roll 在上方横向铺满画布，不加左右留边；如果铺满会切掉关键信息，换合适素材或另做可读的画面，不挤进字幕区。
- **字幕居中隔开**：在上方展示区与下方圆窗之间单留粗白句级字幕带，长句按意群分行，控制在独占区内。标题、图卡、字幕、边线和头像不重叠；逐项检查最长字幕和动画最大外框。字幕按终速原声核准，核对时间、数词和工具专名，剪点改变后重对齐字幕和图卡。
- **下方是真圆中景**：固定居中的正圆，不随上方换画面而缩放或跳位；主体用头肩至胸口的中景，头顶与下巴留余量，不贴脸，不求露全身。边缘只留干净细线，圆外透明、无黑色投影或多边形边缘。真人副本仅用于画面，不引入第二路人声；声画保持同源时间和同一有效语速。
- **Remotion**：需要演示步骤时，用 Remotion 做图卡，内容沿实际词句依次展开，连接线只表示真实步骤，当前重点突出。保留可编辑源和原生时间线实例；渲染实际合成中的入场、展开、停稳及出场，不能以代码导入成功代替验证。
- **配乐早进，声音以人声为准**：配乐按用户认可的曲目，从开场短淡入，第一句附近就可听见但不盖人声。若前奏过轻或太长，先选同曲更稳的段落而不是整曲拉高。沿用青年磁场中已验证的听感目标，仅借鉴混音、不套横屏视觉；音乐平均 RMS 幅度约为人声的 20–30%（约低 10.5–14 dB）可作测量起点，不是固定滑块值。实查首句、低声、停顿、循环接缝、尾部和混音真峰值，缺试听证据要明示。
- **确认与清理**：新上下布局先做约 20 秒代表样片，请用户确认；已有这套明确批准的版式，不反复询问同一规则。确认版须核验成片画幅、圆窗、字幕带、上方全宽 B-roll、音画同步与无重叠。用户选定终稿并授权清理后，先导出和验证指定格式，再清旧审片与确认为不再引用的中间文件，保留原片、终稿、工程与其依赖。1080p60 是按当次要求的交付规格，不固定为品牌默认，也不等同源素材已补帧。

## 约两分钟的观点口播：开口即正文，随后切上下结构

- **片头不是等候页**：从第一句完整原声起播，剪掉录制前的空等，保留字头与自然语气。开头约三秒用与原声同步的全屏真人，主标题在头顶留安全区，沿用本片黑底／白字／绿强调；如需身份卡，置于人物右边，依次弹出，只用用户提供或已核准的称谓，不压脸、不挤平台操作区。第四秒切回上下结构，但音频不重启、不重复第一句、不断话。若第一句跨切换，字幕按意群分段，片头避开脸和身份卡，切换后回到中间字幕带。
- **中间字幕默认不显示标点**：用短句、自然断行或适度空格保证可读性；优先改显示样式而非改写原稿，不改原声、原词或时间。检视片头、切回字幕带的接缝和最长句，不因简洁丢掉语义。
- **动画密度**：约两分钟的同类上下结构观点稿，至少安排 10 段围绕不同论点的 MG 动画，每段约 4–8 秒，以成片中实际可见的时长为准；不把同一张静态卡重复计数。先按台词排出比喻演示、操作示意、流程对比和结论，再在节点间穿插贴题的实拍 B-roll，素材按授权使用并保留出处。动画只留理解内容需要的文字，不加「非实际案例」一类模板式脚注；用明确的抽象图形与去标识的界面表达示意，绝不让虚构记录或图库画面冒充特定现场。
- **审样与验收**：新动画语言或用户要求先审时，先交独立小样，确认后按台词插入；已有明确批准的风格可直接沿用。保留旧版本。检查首句是否从开场即出声、切换时音画字幕是否连续、十段有效可见时长、B-roll 是否挡字或挡脸、片尾文字和标识是否正确。用实际导出校验规格并审片；没有做连续音视频审片就标为待审。
- **品牌例外只按明确要求开启**：阿峰默认仍不带 MC Logo。用户明确指定 MC 关联身份和品牌片尾时，使用获准的身份文案、原版 MC Logo 与用户指定或已确认的收口句，片尾短停留，不把 MC 标识扩展为常驻水印，也不据一次授权改青年磁场技能。

## 完整工作流与必读依赖

安装中已包含完整上游目录，不需要再次索取仓库。开始剪辑前依次读取：

1. [配置契约](references/upstream/contracts/config-contract.yaml)、[可选起始预设](references/upstream/config/optional-presets.yaml)、[项目示例](references/upstream/examples/project.example.yaml)。生成当次配置，填实际项目、单一速度、竖屏输出、所选风格和必做审片项。项目覆盖优先于示例，但不能削弱同步、隐私、直接视听复核和不自动发布底线。
2. [剪辑与同步质检](references/upstream/skills/spoken-video-editing-qc/SKILL.md)：审素材、核准文案和删留、统一segments/frame_map、一次变速、终速干声字幕、混音及质检。不能用静音padding遮盖错位；不能只看容器等长就说同步。
3. [视觉包装](references/upstream/skills/talking-head-style-packaging/SKILL.md)及[风格注册表](references/upstream/styles/catalog.yaml)：时间轴对齐后再做包装，所有卡片跟随内容计划，而不是按固定间隔弹出。旧 `black-neon-talking-head/SKILL.md` 仅为兼容指引，不重复运行两套流程。
4. [执行与验收说明](references/upstream/docs/operations.md)：手机留边/铺满预览、发顶和字幕安全区、各实际布局、剪接点、结尾、人声和音效均需检查。仓库是规范，没有自带可执行渲染脚本。

仓库示例的1.1倍、1440×2560、30fps、18Mbps和−16LUFS均为可选起点，不是所有任务强制值。字幕、音画和动效共用最终时间轴；变速后按终速干声重转写和核准，不机械拉伸旧字幕。无足够能力或输入时说明具体缺项，不伪造结果。
