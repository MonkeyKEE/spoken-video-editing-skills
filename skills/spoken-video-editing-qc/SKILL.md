# 口播剪辑与音画同步质检

## 原则与输入
这是通用工作流，不绑定品牌、人物、私有工程路径或某一软件。本文件是流程与质检模板，不附带可直接执行的渲染脚本，也不构成一键剪辑。读取当次项目配置：原片与参考、品牌、平台、剪辑目标、语速、画幅帧率、字幕和包装方案、音频目标、输出位置。区分用户已确认规范、单次实现与待确认建议；不得把一次复用升级为另一品牌永久规范。项目若已有经过验证的本地脚本，可在检查依赖、参数和版本后沿用。

原片与已有成片分别标记。所有新导出用新版本，不覆盖原片。取材优先走账号授权的安全传输或官方连接器，并用真实文件 ID 核对版本；不改共享权限。不得把公开云盘链接写成取材前提。遇体积或工具限制，先改用其他受支持的安全传输途径；仅当用户明确同意临时公开时才可使用公开链接，用后提醒其关闭。交付限制按当次工具实测，不硬编码历史上限。

若还需要黑底荧光绿人物窗与关键词/章节包装，先完成本技能的统一时间映射、终速干声和逐句字幕，再执行配套技能 [black-neon-talking-head](../black-neon-talking-head/SKILL.md)。

## 1. 探测与审素材
用 ffprobe 记录编码、存储宽高、显示旋转、像素格式、帧率/时基、帧PTS、音轨编号、采样率、声道、start_time、时长。不能仅凭平均帧率判断CFR，也不能假定人声永远在第一音轨。识别横存竖拍与微VFR，按实际显示方向构图。

用可播放的原片或音画同步轻量代理做动态审看。watchVideo 是部分宿主环境提供的看片能力，不是本仓库附带或必须安装的公开命令行工具；若宿主提供该能力，可按该工具要求提交。宿主没有该能力时，必须由人直接看和听，不得跳过，也不得在未看未听时声称已经审过。不能用联系表或静态截图代替动态审片。

## 2. 内容与剪辑表
对原片人声转写，必要时用 faster-whisper 的主模型与对照模型交叉核查。人名、品牌、含混词对原声校对；难句可分段重转写，关闭跨段上下文以排查漏句。

写保留/删除计划，记录每段源起止、理由和文案。不改变原话含义。切点靠近局部能量低点，避免切字、吞尾音和突兀换气。检查接缝前后语义与听感；保留真实尾音和适量自然停顿。

## 3. 单一时间映射与一次变速
建立统一segments与frame_map，至少包括源起止PTS、输出起止帧、累计时长、语速。音频、视频、字幕和动效共用此表。

- 语速只来自一个配置项SPEED；音画各应用一次，禁止在音频滤镜另写死不同atempo。
- 累计输出边界可用 round(累计保留源时长 / SPEED * 输出fps)，由相邻累计边界差得段帧数，避免逐段舍入累积。
- 输出帧对应源时刻须在该保留区间内；VFR按源帧PTS选帧，不用假定恒定帧率的索引。边界舍入不能误带已删除区间的词句。
- 音频裁切使用相同源区间与时间基。采样数按累计时刻换算，保留源音轨start_time偏移；在拼接/变速后统一处理必要的帧或采样量化，并记录误差。
- 当前降噪、变速、压缩链可能引入延迟，必须重测并补偿，不能照抄别条片的采样点数。
- 分别核对有内容的人声结束时间、底视频有效时间轴、计划尾部留白。不能用padding把错误语速的人声撑到同容器时长来伪装同步；真实停顿无需被认定为错位。

保留原速剪辑干声、终速干声、无包装底视频、segments、frame_map和配置快照。

## 4. 最终人声字幕
在终速干净人声上重新转写并按已核准文案校对，不直接比例拉伸旧字幕。结合实际发声边缘修正句起止；难句记录人工修正。字幕、章节、名牌等若使用源时间，均经过同一映射转换。字幕外观由品牌配置决定，时间对齐不能由视觉模板代替。

## 5. 包装、混音与导出
可用Python逐帧图形与FFmpeg分块渲染，保留断点与块边界检查。底视频已变速，包装不可再二次变速。

人声优先，音效只保留有意义的节点，音乐有合法来源且不盖口播。音量百分比、振幅比、分贝与主观响度不是一回事；记录说话时段音乐相对人声的电平并直接听验，必要时duck。不能把单次混音参数当所有品牌标准。

只改配乐：独立干声+音效+新音乐重混，不叠在旧BGM混音上；若要求画面不变，视频stream copy，核对视频流或逐帧hash、PTS与音轨起点，不能要求整个MP4文件hash相同。

可选起始导出预设（非强制）：9:16、1440×2560、30fps CFR、yuv420p、H.264 High约18Mbps、AAC约192kbps/48kHz、MP4 faststart、综合约−16LUFS。按当次平台和用户要求覆盖，测真峰值并留余量；不要用sample peak冒充true peak。语速 1.1× 同样只是可选起始预设，不是所有品牌的硬规范。

## 6. 放行检查
1. 探测导出规格、实际帧PTS、帧数、start_time、时长、分块边界连续性。
2. 检查干声有效内容与映射表，尾部留白可解释；容器等长不能证明同步。
3. 检查源帧映射与实际读取索引；在片头/中/尾、接缝、全屏人物段抽样，报告量化误差，禁止承诺完美逐帧。
4. 用包络互相关对比最终声轨与干声，以及逐段终速人声与按映射取的源人声；记录各段误差是否随时间增长。数值只是辅助，不替代口型。
5. 测综合响度、真峰值、人声/音乐/音效关系，检查失真、接缝、尾音。
6. 卡片不压脸、完整发顶、安全区在目标手机留边和铺满模式都检查。素材来源真实，图库/生成图不冒充真实活动；B-roll不得倒放或循环凑时长。
7. 将最终成片或同时间轴代理交给可直接播放的审片环节，复核片头/片中/片尾、难句与剪接点的口型、字幕、安全区、音效和结尾。videoReview 是部分宿主环境提供的审片能力，不是公开命令行工具；若宿主提供该能力，可以使用。宿主没有该能力时，必须做等价的人工视听审片，不得跳过，也不得在未看未听时声称已经审过。没有做视听审片就标注未审预览和未完成项，不能作为审片通过母带交付。静帧、ffprobe、ASR近邻起点都不等于此步骤。

历史故障教训：视频1.1x、音频误用1.2x可导致尾部约15秒渐进错位，静音padding会使容器时长看似正常，字幕近邻语音起点指标也可能漏检。必须单一变速源、统一映射、有效内容检查和直接视听复核。测得的一次滤镜延迟不适用于所有链路。
